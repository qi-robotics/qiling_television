# Jetson NX 真机遥操开机自启

本目录的两个 systemd 系统服务在 NX 开机满 60 秒后依次启动 XRoboToolkit PC Service 和真机遥操。安装与启用不会立即启动节点；**下次开机**才会自动运行。真机遥操使用现有的 `start_real_teleop.sh`：先等待运控板上的 `/human_lower_state`，收到状态后启动 ROS launch，双臂按照节点现有逻辑从实测姿态经由过渡点回到 home，完成后开放遥操。板子上原有的机器人 SDK、策略和 `qi_topic_converter` 仍由板子自己管理。

## 启用前

- 确认 NX 的 `/home/user/liujun/qiling_television` 是本项目实际路径，工程已在 NX 本机编译，`install/setup.bash` 存在。
- 确认 `config/cyclonedds_nx.xml` 的有线网卡仍是连接运控板的实际网卡；当前部署为 `eth2`、ROS Domain 21。
- 确认 `/opt/apps/roboticsservice/runService.sh` 可运行。不要另装一份会抢占同一 PC Service 的自启单元。
- **每次开机前**清空双臂的运动空间，确认机器人支撑稳定、急停可用。开机后只要板子状态到达，双臂会自动运动到 home；无需等待 Quest 连接或按手柄。

## 一次性安装与启用

在 NX 上运行：

```bash
cd /home/user/liujun/qiling_television
sudo ./src/scripts/install_real_autostart.sh
systemctl is-enabled qiling-xrobotoolkit.service qiling-real-teleop.service
```

安装脚本会复制本目录的两个 `.service` 文件到 `/etc/systemd/system/`，重新加载 systemd 并启用它们。它**不会执行 `systemctl start`**。以后修改本目录的 unit 文件，需再次运行安装脚本使系统副本更新。当前 `install/` 使用源码软链接；只修改脚本或 YAML 配置时无需重新编译 C++，改动在下次服务启动时加载。

## 启动顺序与退出处理

1. `qiling-xrobotoolkit.service` 等待系统运行时间达到 60 秒，使用厂商 `runService.sh` 的运行环境启动 PC Service，并由 systemd 监控进程。进程退出后会重启；一分钟内最多启动三次，超限后停止。
2. `qiling-real-teleop.service` 在 PC Service 进程启动后等待 3 秒，然后执行现有的真机启动脚本。脚本自行加载 ROS、工程 overlay、Domain 21 和 CycloneDDS，并以明确的 `mit_msgs/msg/MITLowState` 类型订阅 `/human_lower_state`，最多等待 **120 秒**接收首条消息。等待时无需先发现板子的发布者；真正超时和 ROS 命令提前报错会分别记录到日志。
3. ROS launch 收到状态后执行节点内的自动回 home。若板子状态始终不到达，遥操服务退出，**不会发布回 home 命令**。
4. 遥操进程异常退出后**不会自动重启**，避免再次无人在场执行回 home。PC Service 停止时，依赖它的遥操服务也会停止。故障排查后需要人工决定是否重新启动。

Quest 可以在开机后再连接 PC Service。连接后打开 Controller Tracking 和 Send；home 完成且 Grip 完全松开后，重新按 Grip 才能接管手臂。

## 查看状态与日志

```bash
systemctl status qiling-xrobotoolkit.service qiling-real-teleop.service --no-pager
journalctl -b -u qiling-xrobotoolkit.service -u qiling-real-teleop.service -n 150 --no-pager
journalctl -f -u qiling-real-teleop.service
```

在另一个终端只读检查 home 完成状态时，先准备与启动脚本相同的 ROS 环境：

```bash
cd /home/user/liujun/qiling_television
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=21 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI="file://$PWD/config/cyclonedds_nx.xml"
ros2 topic echo /teleop/startup_home_complete --once
```

看到 `data: true` 表示自动回 home 已完成。也可从 `journalctl` 查看 `home phase` 和节点报错。不要用手动发布关节或手部命令来验证自启。

## 停止、恢复与取消自启

停止当前遥操，再停止 PC Service：

```bash
sudo systemctl stop qiling-real-teleop.service
sudo systemctl stop qiling-xrobotoolkit.service
```

处理完故障并确认现场安全后，手动启动本次服务：

```bash
sudo systemctl start qiling-xrobotoolkit.service
sudo systemctl start qiling-real-teleop.service
```

这两个手动 `start` 命令会启动真机控制链，遥操节点仍会自动回 home。**不要在服务运行时再执行 `start_xrobotoolkit_real.sh` 或 `start_real_teleop.sh`，也不要运行第二份遥操 launch。** systemd 启动的 PC Service 不使用旧脚本的 PID 文件，应使用 `systemctl stop` 管理。

只取消下次开机自启，不影响当前是否运行：

```bash
sudo systemctl disable qiling-real-teleop.service qiling-xrobotoolkit.service
```

如需同时立即停止，先执行上述 `stop` 命令，再执行 `disable`。重新启用可再次运行 `install_real_autostart.sh`。
