# 动作第二阶段：遥操互斥与状态机

本阶段把动作轨迹接入真机 IK 节点的 50 Hz 控制循环。当前 `config/differential_ik.yaml` 的 `gesture_enabled: true`，launch 启动并完成 home 后即可使用组合键，无需再单独设置参数。代码提交和离线编译不会向机器人发送命令。

## 输入与控制权

`/xr/controller_joy` 中 `buttons[0..3]` 分别为 X、A、Y、B。精确组合 X+A 是挥手，Y+B 是握手，X+B 是抱拳，A+B 是双臂回关节零位并保持；Y+A 是双臂从当前命令构型回 home。组合必须稳定 0.15 秒。除 Y+A 外，两侧 Grip、Trigger 均松开且两侧遥操处于 Hold 时才受理。执行后必须先松开组合键，才能再次触发。

IK 节点独占 `/teleop/arms_mit_command`，并按下列状态运行：

表演动作按 `待命 → 锁定两臂 → 从上一帧命令进场 → 动作摆动 → 关节插值回 home → 反馈到位 → 平滑交接 → 待命` 运行；A+B 在进场后停于零位，再完成反馈到位与交接。

触发时按上一帧命令生成轨迹，检查 URDF 关节限位、关节速度和加速度以及起点反馈误差，随后直接执行；真机触发时不运行网格碰撞预检。动作期间状态超时、控制循环卡顿、反馈跟踪误差过大或终点未到位时进入锁定故障；故障不自动恢复，也不接受 Grip 或新动作。单臂表演动作期间另一臂保持原命令；若其关节起点不足 `0.12 rad` 软件余量，进场阶段只把这些关节平滑带入余量，随后保持。回程时双臂都到各自配置的 home。

所有动作允许从 URDF 硬限位内、但不足 `0.12 rad` 软件余量的命令构型起步；进场轨迹单调地把这些关节带入软件余量。进入动作段后仍要求完整的 `0.12 rad` 余量，关节速度和加速度上限不变。实测关节越过 URDF 硬限位或起点跟踪误差过大时仍拒绝动作。A+B 从上一帧命令连续进入零位，完成后在零位到位并平滑交接。手型命令在状态变化时立即发布，并在状态新鲜时以 10 Hz 重发当前目标；新目标立刻替换旧目标，避免张开后再补发闭合。

NX 首次挥手时，原真机碰撞预检耗时约 6.6 秒；现已取消，状态码 7 保留供旧订阅端兼容，但运行时不再发布。该次动作回 home 后曾因 0.10 rad / 4 秒判据未满足进入状态码 6。现在到位阈值为 0.20 rad、最长等待 10 秒，交接插值为 0.75 秒；日志分别输出左右臂最大关节误差。超限仍锁定故障，不自动交还遥操。组合键仅在两臂可接管时消耗，动作完成后需要释放组合键再触发下一动作。

IK 节点在 `/teleop/gesture_status` 发布内部状态，Grip 桥接节点据此停用两侧遥操目标，结束后要求 Grip 先松开。O6 适配器是唯一 `/handscmd` 发布者；动作期间忽略 Trigger 状态，按阶段发送已换算成 0–255 的手型，回程开始时发送现有标定的双手张开位。故障时 O6 保持上一手型目标，等待人工处理。该内部状态在 0.30 秒内未更新时，桥接节点保持 Grip 锁定，O6 适配器不响应新的 Trigger 状态。

状态码见 `include/qiling_kinematics/gesture_status.hpp`。动作位姿、振幅、周期数和握手内部 1 秒握持等待见 `config/gesture_actions.yaml`；全局微分 IK 限速保持原值。动作结束没有额外停留，到达 home 或零位后仍需完成反馈到位与平滑交接才交还控制权。

离线碰撞检查工具仍可按当前双臂 URDF 的基座、固定腿部、双臂和掌基座网格检查配置动作；它不包含手指实际闭合形状、现场物体及实时腿部姿态。触发动作时不会执行这项检查，现场布置和手型仍须单独验收。
